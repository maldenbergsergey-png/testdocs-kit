# Supplied test evidence

#### Проверка по материалам пользователя

- Использовать уже предоставленные материалы; запросить только недостающие для конкретных пунктов. Скринкаст должен показывать исходное состояние, действия и результат; скриншот подходит для видимого состояния и оформления.
- Сопоставлять видимое с условиями задачи и подтверждённым ожидаемым результатом. Скриншот итогового экрана не доказывает путь к нему, успешный сетевой запрос или сохранение данных после повторного открытия. Не достраивать невидимые действия и поведение между кадрами. Неизвестные сборку, окружение или роль указывать как пробел только если это влияет на применимость результата; не перечислять неизвестные значения ради шаблона.
- Исходный файл, время в видео или время захвата и привязку к строкам сохранять в индексе по [правилам доказательств](execution-evidence-rules.md). Текст отчёта оформлять по [языку результатов](execution-report-rules.md#язык-результатов-тестирования): описывать наблюдаемое состояние приложения, ограничения - через непроверенное поведение или несопоставимые условия. Не переносить в ячейки обороты "По записи", "По скриншоту" или время съёмки. Отсутствие самостоятельного прогона обозначить один раз во вводных, для смешанного отчёта - с номерами соответствующих строк; не выдавать анализ за взаимодействие с приложением.
- Статус выбирать по фактически подтверждённому объёму пункта. Непоказанные действия, состояния и платформы остаются `НЕ ПРОВЕРЕНО` или `ЧАСТИЧНО ПРОВЕРЕНО`; неопределённый ожидаемый результат - `ТРЕБУЕТ УТОЧНЕНИЯ`. Не переносить успешный результат видимой части на весь сценарий.
