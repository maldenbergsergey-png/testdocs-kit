# Web surface

### Проверка браузерных возможностей

- При выборе браузера и любом запросе входа применять [повторное использование сессии](browser-session-rules.md): выбранный пользователем Chrome и читаемая страница имеют приоритет перед новой сессией или авторизацией отдельного коннектора.
- До вывода «нет браузера» проверить доступные инструменты текущего клиента, включая поиск отложенных MCP tools. В OpenCode локальный Playwright MCP пакета называется `testdocs_browser`; ориентироваться на фактические имена выданных инструментов.
- Для UI/SPA использовать браузерную навигацию и snapshot, затем действия по наблюдаемым элементам. Webfetch не заменяет взаимодействие с UI; его transport error не доказывает недоступность стенда, отсутствие браузера или проблему VPN.
- Читать схему фактически доступного инструмента: параметры и набор tools зависят от установленной версии. Если snapshot возвращён ссылкой на локальный файл, прочитать этот файл доступным файловым инструментом и использовать наблюдаемые в нём элементы для следующего действия. Относительные пути `testdocs_browser` разрешать от корня установленного kit (рабочего каталога MCP), а не от произвольного проекта клиента.
- Различать отсутствие MCP, ошибку запуска MCP/Chrome, отсутствие авторизации и сетевую ошибку браузера. Указывать наблюдаемую причину. Если tools недоступны, проверить статус MCP клиента; если доступна только ручная настройка, дать команду `npm run configure:browser` из установленного kit и попросить перезапустить клиент. Не устанавливать интеграцию без запроса пользователя.
- Локальный браузер использует сеть компьютера, на котором запущен MCP. Это не означает автоматическое использование cookies личного браузера. Режим `persistent` открывает отдельный Chrome с сохраняемым профилем; `extension` подключается к выбранной пользователем вкладке Chrome/Edge через официальное расширение. Не копировать cookies и не подменять профиль личным каталогом браузера.
- Подтверждение подключения расширения даёт инструменту доступ к вкладке и не означает, что на сайте нужен повторный вход. После подключения осмотреть целевой контент; если сайт действительно показывает вход, запросить только необходимое действие пользователя по правилам сессии и затем продолжить проверки.
- Профиль авторизации не является доказательством теста. Промежуточные файлы Playwright находятся во временном каталоге вне репозитория; нужные обезличенные доказательства перенести в workspace конкретного проекта/задачи. Не запускать одновременно два прогона с одним persistent-профилем; при конфликте не удалять профиль.
