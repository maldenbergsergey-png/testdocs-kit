# Матрица платформ для QA-оценки

**Редакция:** 2026-09-11. Источники: переданные пользователем PDF "Матрица браузеров, версий и брейкпоинтов для тестирования" (3 страницы) и "Матрица устройств для тестирования мобильного приложения" (1 страница), уточнения процесса в обсуждении. Пользователь поручил учитывать матрицы в навыке. Область применения и проектные замены определяются [профилем](qa-estimation-profile.md) и [правилами команды](qa-estimation-team-rules.md).

Матрица определяет покрытие, а не норматив времени. Формула 25-30% от разработки из web-PDF не применяется: прямое поручение пользователя - оценка по работам и рискам. Числа разрешений ниже являются примерами источника, а не готовой матрицей любой задачи. Дополнительные проверки считаются отдельно от основного покрытия и один раз включаются в итог, если выбраны; это определённый объём работы, а не резерв риска.

## Web: браузеры

Используй актуальную стабильную версию на дату прогона; не выдумывай номер версии. Основной прогон выполняется в desktop-браузере и DevTools на доступном компьютере Windows или macOS. Наличие одной ОС не означает полный прогон обеих. Совпадение движка не отменяет отдельную контрольную проверку указанного браузера; не выводи реальный движок мобильного браузера только из его названия или строки PDF.

| Покрытие | Браузер / платформа | Условие и глубина | Средство |
| --- | --- | --- | --- |
| Базовое Desktop | Google Chrome | Основной прогон web-интерфейса. | Доступный desktop, актуальная стабильная версия. |
| Базовое Desktop | Яндекс.Браузер | Проверки возможных отличий, несмотря на общую основу с Chrome; глубина по риску и тест-дизайну. | Актуальная стабильная версия. |
| Базовое Desktop | Safari macOS | При поддержке Safari в проекте. | Доступный Mac; при отсутствии - доступная ферма, например BrowserStack. |
| Базовое Mobile Web | Chrome Android | При наличии mobile web и согласованных mobile-макетов: финальная контрольная проверка ключевых экранов и основных сценариев. | Доступный Android; при отсутствии подходящего устройства - ферма. |
| Базовое Mobile Web | Яндекс.Браузер Android / iOS | Контроль ключевых экранов и основных сценариев на выбранном доступном мобильном устройстве, переиспользуя подготовку. | Актуальная стабильная версия на том же доступном Android/iOS; при отсутствии - ферма. |
| Базовое Mobile Web | Safari iOS | При наличии mobile web и согласованных mobile-макетов: финальная контрольная проверка ключевых экранов и основных сценариев. | Доступный iPhone; при отсутствии подходящего устройства - ферма. |
| Дополнительное | Edge, Opera, Brave, Samsung Internet; другие требуемые браузеры | По требованиям или данным аналитики; отдельно от основного покрытия. | Подтверждённые конфигурации. |
| Расширенное | Старые, корпоративные или конкретные версии браузеров | Только по согласованной дополнительной матрице. | Отдельная оценка и доступный способ проверки. |

Mobile Web не требует полного повторения всех экранов, состояний и сценариев desktop. Выбери репрезентативные сочетания по тест-дизайну, сохрани нужные платформенные проверки. Контроль Яндекс.Браузера на Android/iOS не означает автоматически полный прогон на обеих платформах или добавление Chrome iOS в базу.

По устным правилам команды для web нужен минимум один реальный мобильный контроль; для другой требуемой платформы можно привлечь коллегу или ферму. PDF допускает ферму при отсутствии подходящего устройства: обозначь такую замену и границы проверки явно. Если ни одного реального устройства/подходящей фермы нет, DevTools не подтверждает этот контроль - оставь ограничение и нужный объём. Ферма как способ выполнить ту же базовую конфигурацию не создаёт второй полный прогон; её активная настройка учитывается. Расширение моделей, ОС или сценариев через ферму оценивается дополнительно. Не считать доступ к BrowserStack, нужному браузеру или аппаратной функции уже имеющимся без подтверждения.

## Web: брейкпоинты

| Область | Примеры из PDF, px | Условие включения и предмет проверки |
| --- | --- | --- |
| Mobile | 375 | Только если соответствующее состояние отрисовано и согласовано. Отображение, доступность элементов, навигация, формы, критичные поломки вёрстки. |
| Tablet | 768 | Только если отрисовано и согласовано. Перестроение сеток, карточек, таблиц, меню и основных экранов. |
| Desktop | 1440 | Только если отрисовано и согласовано. Структура, блоки, формы, таблицы, модальные окна и ключевые сценарии. |
| Дополнительные макетные | 1024 / 1280 / 1920 | Если отдельно отрисованы и согласованы. По источнику входят в основной объём, когда учтены в оценке разработки; иначе показать дополнительную работу. При неизвестности уточнить включение или оценить отдельной строкой. Часы в обоих случаях считаются по QA-работам, не процентом. |
| Разрешения сверх макетов | 320 / 360 / 390 / 414 / 1366 / 1536 | Не обязательная часть основной оценки. По отдельному запросу/оценке либо при оставшемся времени; такое необязательное покрытие нельзя обещать в фиксированном итоге. |
| Полная проверка промежуточных разрешений | Отдельно согласованный набор | Расширение, оцениваемое отдельно. |

Бери реальные значения из текущих согласованных макетов, не подставляй эти примеры при отсутствии макета. Не исключай согласованную проверку молча из-за неизвестной оценки разработки: покажи её объём и допущение отдельно. Увеличение числа брейкпоинтов в оценке разработки не создаёт автоматической надбавки в процентах и не разрешает двойной учёт того же адаптивного прогона.

Проверка web на tablet-брейкпоинте не означает автоматическую закупку/аренду физического планшета или включение планшета в базовую матрицу нативного приложения. Матрица выполнения не создаёт отдельные постоянные Test Cases на каждую ширину: правило основного desktop breakpoint для постоянных web-кейсов сохраняется.

## Мобильные приложения: iOS и Android

Базовый ориентир - по одному доступному реальному устройству каждой затронутой платформы у тестировщика/компании, обычно два устройства для задачи на iOS и Android. Одноплатформенная задача не получает вторую платформу автоматически. Существование конкретного устройства и сборки нужно подтвердить; модель не угадывать.

| Покрытие | Устройство / ОС | Глубина и условия |
| --- | --- | --- |
| Базовое iOS | Доступный реальный iPhone, актуальная поддерживаемая iOS; ориентир переданного PDF - iOS 26.x | Применимые к задаче установка, авторизация, ключевые сценарии, пуши, камера, файлы, геолокация и общее поведение. |
| Базовое Android | Доступный реальный Android; диапазон переданного PDF - Android 13-16 | Основной прогон с учётом оболочки производителя. Диапазон не означает четыре полных прогона всех версий. |
| Дополнительное iOS | iPhone другой диагонали/поколения, поддерживаемая iOS | Отображение, адаптивность и базовые сценарии; ферма, коллега или доступное реальное устройство. |
| Дополнительное Android | Samsung, Xiaomi, Redmi, POCO, Realme, Honor; Android 13-16 по источнику | Выбранные модели/оболочки и отображение/поведение; ферма, коллега или доступное реальное устройство. Это перечень направлений расширения, не обязательный комплект брендов. |
| Расширенное | Планшеты, foldable, Huawei без Google-сервисов, старые ОС, конкретные модели заказчика | Отдельное требование, способ проверки и оценка. Не входит в базовый мобильный набор. |

Числа версий фиксируют переданную редакцию матрицы, а не вечный перечень актуальных ОС. Учитывай текущую поддержку проекта и фактическую конфигурацию; обновление версии матрицы не выдумывай. Справочные утверждения PDF о доступности ОС/моделей не являются подтверждением текущей доступности устройства.

Симуляторы и Android-эмуляторы возможны, но используются реже, чем реальные устройства. Ферма расширяет покрытие и не считается универсальной заменой физических проверок пушей, камеры, файлов, биометрии, геолокации, производительности или нестабильной сети. Для нужной аппаратной функции явно укажи доступность и ограничение способа проверки; не добавляй все перечисленные функции любой задаче.
