# Передача мобильного приложения агенту

Тестировщик устанавливает сборку на выбранное устройство, открывает приложение и передаёт задачу. Агент проверяет фактическое подключение и исходный экран, затем выполняет проверки по [мобильным правилам](../rules/execution-native-rules.md). Уже готовое приложение не нужно переустанавливать, перезапускать или повторно авторизовывать ради подключения.

## Какое подключение использовать

| Компьютер и устройство | Обычный выбор | Что подготовить |
| --- | --- | --- |
| Windows/macOS, Android Emulator или телефон | Готовый Maestro MCP; Appium при явном выборе или отсутствии Maestro | Установленное приложение и доступ по ADB; для телефона USB debugging |
| macOS, iOS Simulator | Готовый Maestro MCP; Appium также поддерживается | Runtime Simulator и установленная сборка для Simulator |
| macOS, физический iPhone | Appium MCP | Установленное приложение и работающий WDA/Appium |
| Windows, физический iPhone | Appium MCP через подготовленный Appium server | Совместимые версии Windows/iOS/Appium, подписанный WDA и туннель |

Одна задача может использовать Maestro для Android и Appium для iOS. Оба MCP доступны в одном чате; отдельные чаты для платформ не обязательны. Агент закрепляет устройство и сессию каждого подключения, сохраняет отдельные результаты платформ. Это не означает синхронных нажатий: параллельность зависит от клиента и независимости данных.

Appium имеет смысл на Mac для физических iPhone либо когда проект уже использует Appium. Работающий Maestro для Android/Simulator менять ради этого не требуется. Официальный Maestro не поддерживает физический iPhone. См. [Android Maestro](https://docs.maestro.dev/get-started/supported-platform/android), [ограничения iOS Maestro](https://docs.maestro.dev/get-started/supported-platform/ios/uikit), [Appium MCP](https://github.com/appium/appium-mcp).

## Минимум от разработки и проекта

Запрашивать только артефакты для выбранных целей:

| Цель | Что передать тестировщику |
| --- | --- |
| Android Emulator/телефон | Устанавливаемая APK с подходящей архитектурой; package ID |
| iOS Simulator | `.app`, собранная именно для iOS Simulator и архитектуры Mac; bundle ID |
| Физический iPhone | Устанавливаемая подписанная сборка, например IPA для зарегистрированного телефона, либо доступный проектный канал установки; bundle ID |
| Физический iPhone через Appium | Дополнительно подготовленный подписанный WebDriverAgentRunner, его bundle ID и совместимые версии WDA/XCUITest; порядок обновления подписи |

Для каждого приложения нужны версия/номер сборки, целевой backend и способ получить тестовый аккаунт/данные. VPN и зависимости сценария, например получение OTP, описываются только когда они нужны проекту. Секреты передаются приватно; не добавлять их в capabilities, общие инструкции, flows или отчёты.

Для Maestro/Appium не требуется встраивать библиотеку автоматизации в продукт или передавать агенту исходники. Отдельная сборка для Simulator нужна из-за целевой платформы; извлечение `.app` из IPA для телефона её не заменяет. Если проект тестирует и Simulator, и iPhone, нужны оба варианта сборки; для одной цели запрашивать второй не нужно. Уникальные accessibility ID полезны для нестандартных/неоднозначных контролов, но не являются обязательной доработкой каждого экрана перед началом осмотра.

Обычная передача каждой новой сборки: артефакт/канал установки, app ID, версия и окружение. WDA относится к подготовке устройства; заново готовить его для каждой сборки продукта обычно не требуется.

## WDA для физического iPhone

WebDriverAgent - отдельный служебный runner на телефоне. Самая короткая передача от iOS-разработчика:

1. Получить UDID и версию iOS выбранного телефона. Согласовать с тестировщиком версии Appium/XCUITest и способ подписи WDA.
2. На Mac с Xcode подготовить совместимый `WebDriverAgentRunner-Runner.app`: выбрать signing team и bundle ID, профиль с нужным устройством. Для запуска без Xcode использовать подготовку preinstalled WDA, включая требования к встроенным XCTest-библиотекам; необходимые изменения пакета делать до окончательной подписи.
3. Подписать WDA, установить или передать готовый устанавливаемый пакет тестировщику. Передать bundle ID, версию WDA, срок действия подписи и контакт для её обновления. Закрытый ключ подписи тестировщику для обычного использования готового пакета не нужен.
4. Совместно с тестировщиком подтвердить запуск именно через выбранный маршрут: создание Appium-сессии, чтение дерева, снимок, нажатие и ввод в тестовом приложении. Иконка WDA или его установка не подтверждают рабочую автоматизацию.

Код WDA писать с нуля не требуется. [Официальная процедура preinstalled WDA](https://appium.github.io/appium-xcuitest-driver/latest/guides/run-preinstalled-wda/) допускает подготовку на Mac и последующую установку сторонними утилитами. Готовый пакет должен сохранять возможность запуска XCTest; обычная переподпись IPA приложения через Sideloadly сама по себе это не проверяет.

Подпись обслуживается отдельно от выпуска приложения. Истечение профиля, добавление телефонов или обновление несовместимых версий могут потребовать нового пакета WDA. Бесплатный Personal Team требует переподготовки после истечения семидневного профиля; для регулярных прогонов удобнее профиль команды проекта. [Ограничения Personal Team](https://developer.apple.com/help/account/basics/about-your-developer-account).

## Подготовка компьютера тестировщика

Разово установить выбранные Maestro/Appium MCP и платформенные инструменты. Установщик Kit подключает уже установленный MCP, но не скачивает SDK, WDA или приложения. Режимы и диагностика описаны в профилях [Maestro](../integrations/profiles/maestro.md) и [Appium](../integrations/profiles/appium.md).

Для Appium на Windows нужен отдельный подготовленный Appium server с XCUITest driver. Использовать совместимые зафиксированные версии по инструкции проекта; мастер локальной подготовки iOS в Appium MCP рассчитан на Mac. Описанный в документации Windows-маршрут имеет ограниченную поддержку и требует физического iPhone с iOS 18+, Apple Mobile Device drivers, доверия компьютеру, Developer Mode, developer image и RemoteXPC-туннеля. Сверять требования с версиями по [Non-macOS Hosts](https://appium.github.io/appium-xcuitest-driver/latest/guides/non-macos-hosts/) и [RemoteXPC](https://appium.github.io/appium-xcuitest-driver/latest/guides/remotexpc-tunnels-real-devices/).

Подготовленный сервер можно запустить локально на Windows; `remoteServerUrl` означает подключение MCP к отдельному Appium server и не требует облака или другого компьютера. Например, endpoint сервера может быть `http://127.0.0.1:4723`. Реальный адрес берётся из настроек проекта, не угадывается по примеру.

Для уже установленного и открытого iOS-приложения передать capabilities без `appium:app`:

```json
{
  "platformName": "iOS",
  "appium:automationName": "XCUITest",
  "appium:udid": "<UDID выбранного iPhone>",
  "appium:platformVersion": "<версия iOS>",
  "appium:bundleId": "<bundle ID тестируемого приложения>",
  "appium:usePreinstalledWDA": true,
  "appium:updatedWDABundleId": "<настроенный bundle ID WDA>",
  "appium:noReset": true,
  "appium:autoLaunch": false
}
```

Заменить placeholders значениями проекта; учитывать `.xctrunner` suffix по инструкции WDA. Если WDA уже запущен и управляется отдельно, вместо preinstalled-настроек можно передать предоставленный `appium:webDriverAgentUrl`. Агент сверяет эти параметры с реальной схемой подключения и задачей. Установка или холодный запуск приложения проверяются с отдельными условиями соответствующего сценария.

## Что передать агенту в задаче

Достаточно назвать задачу, устройства и уже известные настройки. Поля не нужно запрашивать повторно, если они доступны в подключении или проектном контексте.

```text
Проверь сохранение имени профиля на Android и iOS по требованиям задачи.
Оба приложения открыты на тестовом стенде, тестовые аккаунты готовы.
Android: Maestro MCP, выбранное устройство <ID>, приложение <package ID>.
iOS: Appium MCP, iPhone <UDID>, приложение <bundle ID>.
Appium server: <URL>, capabilities: <файл в workspace проекта>.
Если сессия уже создана: sessionId <ID>.
Требование: после сохранения имя остаётся новым при повторном открытии профиля.
```

Готовая Appium-сессия удобна, но не обязательна: агент может создать её на подготовленном сервере по переданным capabilities, сохранив состояние приложения. При готовой сессии он делает attach и не удаляет её после осмотра. Достаточность передачи подтверждается чтением экрана приложения; успешный запуск CLI или зелёный статус MCP не заменяют эту проверку.
