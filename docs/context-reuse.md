# Сохранённый контекст связанных задач

Агент сохраняет уже собранные требования и наблюдения локально и использует нужные разделы для продолжения или связанной задачи. [Правила переиспользования](../rules/context-reuse-rules.md) определяют актуальность, полномочия источников и платформенную применимость. Сохранение не меняет запрошенный артефакт и не подтверждает новый прогон.

Хранилище находится в `context/` пользовательского data directory из [настройки workspace](installation.md#локальная-история-тестирования), отдельно от checkout и папок отчётов/доказательств. `TESTDOCS_DATA_DIR` выбирает другое место. Установщик переносит helper вместе со скиллами, но не создаёт и не удаляет пользовательский контекст.

## Процедура для агента

1. Определить точное подключение, проект и подтверждённую связь с фичей. Для задачи без такой связи использовать её собственный ключ. Записать известную ветку/релиз как `scope`, иначе `current`; не угадывать версию или платформу.
2. Если материалы уже сохранены, вызвать `list` в этом feature/scope. Индекс содержит краткое описание, источники и названия разделов, без подробного текста. Выбрать только разделы для текущего результата.
3. Проверить актуальные версии выбранных источников через доступное адресное чтение. Если версия недоступна, прочитать нужный материал заново; сравнение fingerprint требует заново полученного полного исходного материала соответствующего scope. Проверять решения в комментариях отдельно, если они влияют на ожидания. Полный актуальный текст, уже supplied для текущей задачи, повторно не запрашивать.
4. Подготовить `current-sources.json` из фактически полученных проверок и вызвать `read` с конкретными разделами и целевой платформой. Обновить изменившиеся/неполные разделы, дочитать требования самой новой задачи, исключения и макеты. Решение о достаточности принимает скилл результата.
5. Сохранить новое содержимое через `save`, если локальное сохранение допустимо и идентичность однозначна. В установленной копии запускать helper из resource root, доступного по ссылке скилла, а не искать `scripts/` в рабочем проекте пользователя.

## Контракт входного файла

[Пример](../examples/good/reusable-feature-context.json) вымышленный; его значения нельзя использовать как требования реального проекта.

| Поле | Содержание |
| --- | --- |
| `version` | `1` |
| `identity` | Непустые `connection`, `project`, `feature`, `scope`, `task`, `platform`. `connection` обозначает точную настроенную instance; если одинаковый ID используется в двух установках с общим data directory, использовать instance-qualified ID. Для ручного контекста нужна явно заданная локальная область, например `manual:demo` |
| `summary` | Краткое описание для выбора материалов, максимум 6000 символов. Это ограничение символов, не подсчёт токенов |
| `sources` | Список уникальных `id`, точных `ref`, `revision` (строка или `null`), `authority`, `completeness`, `retrievedAt`; необязательный `fingerprint` - SHA-256 полного исходного материала нужного scope |
| `authority` | `requirement`, `decision`, `observation` или `practitioner`; определять по фактическим полномочиям источника |
| `completeness` | `COMPLETE`, `PARTIAL` или `UNAVAILABLE` для явно ограниченного материала. Пробелы не скрывать в кратком описании |
| `sections` | Уникальные `id`, `title`, `kind`, `platforms`, `sourceIds`, полный `content` нужного раздела |
| `kind` | `requirements`, `inventory`, `analysis` или `coverage`. Раздел требований допускает источники только `requirement`/`decision` |
| `platforms` | Явно подтверждённые платформы раздела. Платформа снимка должна входить в список, кроме снимка `shared`. Значение `shared` - область хранения, а не свидетельство общей применимости |

Технические ID источников/разделов содержат буквы ASCII, цифры, `_` и `-`, максимум 80 символов. Даты записываются в ISO 8601. Неизвестные поля отклоняются; credentials, статусы исполнения и секретные ссылки в этот контракт не входят. Историю результатов оставлять в task workspace.

## Команды

Из checkout/deployed kit:

```bash
npm run context -- save --file /absolute/task-workspace/requests/context.json
npm run context -- list --connection demo-jira --project DEMO --feature DEMO-100 --scope current
```

В установленном resource bundle эквивалент: `node /absolute/resource-root/scripts/context-store.mjs ...`.

Для iOS можно выбрать общий раздел из Android-снимка, если источник прямо описывает обе платформы. `--platform` указывает происхождение снимка, а `--target-platform` - новую платформу:

```bash
npm run context -- read --connection demo-jira --project DEMO --feature DEMO-100 --scope current --task DEMO-101 --platform android --target-platform ios --section name-rule --current-sources /absolute/task-workspace/requests/current-sources.json
```

`current-sources.json` содержит реальные текущие проверки, а не скопированные даты старого снимка:

```json
{
  "identity": {"connection": "demo-jira", "project": "DEMO", "feature": "DEMO-100", "scope": "current"},
  "sources": [{
    "id": "profile-spec",
    "ref": "https://wiki.example.invalid/pages/77",
    "revision": "3",
    "completeness": "COMPLETE",
    "checkedAt": "2026-10-05T10:00:00Z"
  }]
}
```

`check` принимает те же аргументы и возвращает только проверки. Без `--section` он проверяет метаданные всех разделов этого снимка. `read` требует явного выбора; повторить `--section` можно для нескольких разделов. Без актуальных проверок подробное содержимое не выдаётся. У `list` есть дополнительные точные фильтры `--task` и `--platform`.

Статусы источников: `CURRENT`, `CHANGED`, `UNVERIFIED`, `PARTIAL`, `UNAVAILABLE`. Разделы возвращают `CURRENT`, `NOT_APPLICABLE` или `REFRESH_REQUIRED`; только `CURRENT` содержит `content`. Общий статус `PARTIAL_REUSE` означает, что годна лишь часть выбранных разделов. Он не означает готовность всей документации. Совпадения даты получения, заголовка и локального hash раздела недостаточно для актуальности; противоречие revision/fingerprint требует обновления.

Снимки неизменяемые и адресуются hash метаданных/разделов; атомарный `latest.json` выбирает последний. Повторное сохранение одинакового материала не дублирует его, новый снимок сохраняет предыдущий. Helper проверяет локальную целостность, но не обращается к внешним системам и не может подтвердить честность переданных метаданных. Сохранением одного scope управляет основной агент; параллельные исполнители возвращают материалы ему.

## Экономия и модели

Экономия появляется при адресном чтении и анализе нужных разделов. Загрузка всех сохранённых материалов в каждый чат её убирает. Сравнивать полный расход всех исполнителей, повторные чтения, время и пропуски требований. Если клиент не отдаёт usage, не объявлять точную экономию токенов по длине файла.

[Модельные роли](../rules/model-routing-rules.md) можно включать отдельно. Для Codex есть [профиль с шаблонами](../integrations/profiles/codex-model-routing.md): выбранная модель остаётся в основном чате, отдельные подзадачи могут получить другую модель.
