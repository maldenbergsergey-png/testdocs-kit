# Как настроить, запустить и написать мобильный автотест

Каждый проект хранит свои сценарии в Git. Мобильные сценарии описаны в YAML на командах Maestro. Скрипт проекта выбирает устройства и тесты. Если проект подключил Allure, там можно открыть отчёт по прогону.

## Первый запуск на компьютере

Открой README проекта. В нём нужны адрес репозитория, способ получить тестовую сборку и доступы, команды запуска для твоей системы, а также ссылка на отчёты. Установи зависимости из этого README. [Установка Testdocs Kit](installation.md) нужна, если планируешь работать через агента.

| Где запускаешь | Что подготовить |
| --- | --- |
| Windows, PowerShell | Git, инструменты проекта и Maestro CLI. Для Android нужны SDK Platform-Tools и запущенный эмулятор или подключённый Android. |
| macOS, Terminal | Те же инструменты для Android. Для iOS Simulator нужны Xcode и подходящая сборка для симулятора. |
| Реальный Android по USB | Включи USB-отладку и подтверди подключение к компьютеру. В `adb devices` должно быть устройство со статусом `device`. Тест выполняет Maestro. |
| Реальный iPhone по USB | Нужны тестовая сборка и подготовленные Appium, XCUITest и подписанный WebDriverAgent. Для запуска сохранённого YAML используй совместимый runner через HTTP API Appium. |

[Установка Maestro](https://docs.maestro.dev/maestro-cli/how-to-install-maestro-cli) · [Подготовка Android и iPhone, включая Windows](mobile-testing.md) · [Команды для физических устройств](../integrations/profiles/mobile-test-runners.md)

Если хочешь, чтобы агент всё настроил, отправь такой запрос в своём AI-клиенте и подставь ссылку на проект и свои устройства.

```text
Настрой мобильные автотесты на моём компьютере. Вот репозиторий проекта [ссылка].
Нужен запуск на [устройства]. Проверь, что уже установлено, и настрой недостающее.
Прогони один сохранённый smoke, покажи результат и оставь команды для следующих запусков.
```

Агент выполняет доступные действия на компьютере. Ввод пароля или токена, подтверждение доверия телефону и другие интерактивные шаги выполняй по запросу в соответствующем окне. При необходимости добавь к запросу «Опубликуй пробный отчёт в Allure проекта».

## Как запускать

1. Открой тестовую сборку на выбранных устройствах. Если кейсу нужна авторизация, подготовь тестовый аккаунт. Для гостевого сценария используй гостевую сессию.
2. Открой терминал в папке репозитория. Для готовых тестов обнови основную ветку по README. Свои изменения проверяй из своей рабочей ветки.
3. Скопируй из README одну команду для нужной цели. Для запуска на обеих платформах подготовь обе цели. Если подключено несколько устройств, укажи нужное по инструкции проекта.

Ниже примеры для проекта с командой `npm run mobile`. Скопируй один нужный блок в терминал. Если PowerShell блокирует `npm.ps1`, замени `npm` в команде на `npm.cmd`. Имена скриптов и наборов проверь в README проекта.

**Весь набор Android**

```sh
npm run mobile -- android
```

**Весь набор iOS**

```sh
npm run mobile -- ios
```

**Обе платформы**

```sh
npm run mobile -- both
```

**Один кейс по ключу из Zephyr**

```sh
npm run mobile -- android --case DEMO-T42
```

**Группа тестов**

```sh
npm run mobile -- android --group profile
```

**Список сценариев без запуска**

```sh
npm run mobile -- android --list
```

Подставь свой ключ вместо `DEMO-T42` или свою группу вместо `profile`. Для нескольких кейсов укажи `--case` перед каждым ключом, если проект предусматривает этот фильтр. Для физического iPhone выбери профиль Appium проекта.

После запуска проверь итог и путь к сохранённому результату. Если публикация включена, открой ссылку на этот прогон в Allure и выбери нужную платформу. Статус публикации проверяй отдельно от статуса теста. Сохрани подготовленные результаты, чтобы повторно отправить их при сбое публикации. [Настройка токена Allure](../integrations/profiles/mobile-test-runners.md#настройка-токена-allure) · [Пошаговый отчёт](../integrations/profiles/mobile-test-runners.md#пошаговый-отчёт-в-allure)

## Как написать тест по кейсу

Открой нужную сборку и передай агенту ссылку на кейс и платформы. Скопируй запрос в чат своего AI-клиента.

```text
Используй automate-mobile-tests. Автоматизируй кейс [ссылка] для [платформы].
Сохрани YAML в репозитории проекта и сверь его с ожидаемыми результатами кейса.
Запусти сохранённый тест. Покажи команду, результат на каждом устройстве и путь или ссылку на отчёт.
```

Сверь в результате значимые тексты, состояния элементов и итог действия. Повтори тест на рабочей ветке по команде агента. В merge request приложи ключ кейса, проверенные платформы, сборки и отчёты. При разных экранах Android и iOS используй отдельные YAML с одним ключом кейса. Общие действия выноси в `subflows/`. Если тесту подходит любой объект, дай ему выбрать доступный и проверить результат для выбранного объекта.

## Что заполнить при подключении другого проекта

В README нового проекта укажи репозиторий, площадку сборок, поддерживаемые цели, команды первого запуска, повседневные команды и адрес отчётов. В конфиге проекта храни открытые App ID, ссылку на стенд, группы и пути к наборам. Профиль телефона, авторизацию и токены передавай через приватные настройки или секреты CI. Общую памятку подключай ссылкой. [Структура набора и правила для физических устройств](../rules/mobile-automation-structure-rules.md)
