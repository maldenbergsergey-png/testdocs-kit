# Tester execution statistics

Read the [statistics contract](../../../rules/test-run-rules.md#execution-statistics) and [Zephyr evidence mapping](../../../integrations/profiles/zephyr-scale.md#execution-statistics) for this branch only.

1. Resolve the exact connection and run. Search/paginate candidate runs only inside known project/folder scope. A name such as "current regression" is usable when current scoped evidence identifies one run; a bare `101` across several projects is insufficient. Ask for its project/full key/link while continuing independent work.
2. Use the known user timezone, not the server/process timezone. If it is unknown, ask for it. Call `zephyr_get_test_run_statistics` with `testRunKey`, IANA `timeZone`, and either `date: YYYY-MM-DD` or inclusive `startDate`/`endDate`. Omit all date fields for today. Use exact configured `initialStatuses` if they differ from `Not Executed`; do not translate raw status names.
3. The default call inventories every execution with `onlyLastExecutions=false`, then reads the version-dependent internal UI audit through the existing transport. It retrieves the project's status dictionary, membership history and every execution's status-change history with all pages, validates creation anchors and checks that membership remained stable. `HISTORY_BASED` uses actual audit authors and change times; `PARTIAL_HISTORY` excludes unverifiable cases. This read needs no management opt-in. Use `historyMode: public_records` only when the user specifically limits the scope to public API/saved executions. On unsupported/failed audit the tool returns `HISTORY_UNAVAILABLE`, `rows: null`, `totals: null` with the actual failure. Do not derive an exact table from `run.items`, assignments, execution dates, or the latest saved statuses; an empty public results list alone does not prove zero work.
4. If the live audit is unavailable but a complete export exists, inspect its source, scope, completeness, actor semantics and timestamp semantics before using `historyPath`. Normalize actual transition events to the profile's v1 file contract in the task workspace outside the pack. Preserve source evidence; never create events by comparing mutable executions or renaming `executedBy`/`updatedBy` as a verified transition actor. The tool validates structure/coverage and returns a source hash; it cannot verify an export's completeness against Zephyr. State that provenance in the report. An accessible UI history can be used only after confirming that it covers all transitions, actors, configurations and the cutoff; do not guess private endpoints.
5. When history is unavailable, describe the available alternative. For a saved-execution summary or a request to explore available statistical alternatives, call with `includeRecordedSummary: true`. Label its table "Сводка сохранённых выполнений; переходы за день и исторические статусы не подтверждены". Use `recordedSummary`, not the unavailable exact totals. Missing authors/times and ambiguous ties are excluded with a count. A summary cannot recover overwritten/deleted records or prove a case started from the initial status that day.
6. Render returned rows as `Тестировщик | <raw status columns> | Всего` and add `Итого`. Use `displayName` plus `userKey` where names collide; keep a key when name lookup is unavailable, including inactive users. Include the clickable run, local dates/timezone, report cutoff for an unfinished day, counting/attribution rule and relevant excluded-case count. For multiple days label total as case-days and show `uniqueCases`; every counted day of a case uses that case's status at the end of the whole selected period, while credit stays with each day's actor. Do not recompute columns by each day's closing status. `PARTIAL_HISTORY` is a subtotal of confirmed included cases, never a complete run total. For a reset retain the final initial-status column instead of silently dropping the counted work.

For "сколько человек" count distinct included actual actor keys. If the user asks how many cases were "закрыты", state the statuses included in that subtotal and show active statuses such as `In Progress` separately; do not silently call active work closed or change the initial-transition eligibility rule. Keep the full execution total distinguishable from the closed subtotal.

If this tool is absent in an older running MCP, report the capability gap. Existing `zephyr_get_test_run_results` can inspect saved records with all pages but cannot establish a transition audit. Developing the pack does not authorize changing an installed copy or client configuration; deployment and MCP restart are separate operations.
