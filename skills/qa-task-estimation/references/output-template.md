# Краткая оценка для комментария

Следуй [методике](../../../rules/qa-task-estimation-rules.md). По каждой задаче возвращай самостоятельный компактный блок для переноса пользователем в комментарий. Оставляй только полезные строки; шаблон не задаёт нормативы или обязательность направлений и не разрешает публикацию.

**<Ключ/название с известной ссылкой>: <T> чел.-ч для планирования.**
Статус: <предварительная экспертная / уточнённая; основание часов>.
Базовая работа: <B> чел.-ч. Резерв: <R> чел.-ч.

Границы: <изменение именно этой задачи, платформы, зависимости от головной/соседних задач и существенные исключения>.
Основание: <правила команды с источником/редакцией, сопоставимая история или экспертное суждение>.

| Часть | Что входит и почему столько времени | Стенд и этап | Чел.-ч |
| --- | --- | --- | ---: |
| Анализ и подготовка | <исследование, коммуникации, данные и роли> | <общая часть или конкретная среда> | <часы> |
| Бэкенд/API | <сущности, контракт, логика; объём этой задачи> | <Dev: часы; Stage: часы> | <сумма> |
| Фронтенд | <поведение, связка с API, макетные ширины и контрольные браузеры> | <Dev: часы; кросс Stage: часы> | <сумма> |
| iOS | <свои сценарии, устройство и особенности> | <включённые этапы> | <часы> |
| Android | <свои прогоны и особенности> | <включённые этапы> | <часы> |
| Интеграции | <своя сторона и совместный обмен, не учтённые выше> | <доступные среды/этапы> | <часы> |
| Документация | <чек-лист, кейсы, валидация результатов ИИ и исправления> | <где нужны> | <часы> |
| Регрессия / smoke | <конкретные сценарии или доля общего прогона с местом учёта> | <Stage: часы; Prod: часы> | <сумма> |
| Ретест и результат | <циклы, объём и повторная подготовка> | <нужные этапы> | <часы> |

**B = <часы>; R = <часы>; T = B + R = <часы> чел.-ч.**

После таблицы кратко укажи существенные допущения; для каждого риска - дополнительную работу, часы и основание; что изменит оценку; уверенность с причиной; необходимые вопросы. Ожидание и календарный прогноз отдельно. "Нужно уточнить" не подменяй нулём. Назови реально прочитанные источники полезными ссылками, без внутреннего context bundle.

Для простой задачи можно объединить связанные работы, сохранив видимость частей, этапов и арифметику. Автоматизацию и специальные проверки добавляй при включении в scope. Не выводи пустые строки для неприменимых платформ. Если строка включает Dev и Stage, раскрой часы этих этапов и итог один раз.

## Пакет

После отдельного блока каждой задачи добавь сводку. Здесь вклад задачи означает только её уникальную работу, а не полный самостоятельный цикл. В соответствующем блоке напиши: "Оценка в составе пакета; общие работы указаны отдельно".

| Задача / общий объём | База, чел.-ч | Резерв, чел.-ч | Для планирования, чел.-ч |
| --- | ---: | ---: | ---: |
| <Задача A: уникальный объём> | <B_A> | <R_A> | <B_A + R_A> |
| <Задача B: уникальный объём> | <B_B> | <R_B> | <B_B + R_B> |
| Общие работы | <подготовка, документация, пересекающаяся регрессия> | <общие риски> | <сумма> |
| Проверки взаимодействия изменений, если нужны | <часы> | <риск без пересечения> | <сумма> |
| Итого пакет | <B пакета> | <R пакета> | <T пакета> |

Объясни, при каких сборках, данных и порядке поставки общие работы можно выполнить один раз. Самостоятельные оценки, если они запрошены, вынеси отдельно и объясни разницу с пакетной суммой.

При распределении общих часов по задачам покажи доли и не прибавляй общую строку ещё раз.

## Диапазон, пересчёт и факт

Для диапазона добавь согласованные сценарии: условие, B, R, T. Отметь, что резерв уже входит в T, и обоснуй выбор для планирования. Не суммируй несовместимые максимумы.

Для пересчёта добавь строки "Блок / Было / Стало / Дельта / Причина" и обновлённые B/R/T. Для сравнения с фактом используй "Блок / Оценка / Факт / Отклонение / Объяснение"; отдельно покажи изменение scope, реализованные риски и ожидание. При отсутствии исходных чисел не выдумывай их.

Для дней сохрани человеко-часы и укажи согласованное количество часов рабочего дня; календарный прогноз отдельный, с загрузкой и зависимостями.

Для вариантов выпуска используй "Вариант / Задачи и зависимости / Бизнес-результат или скрытая поставка / Проверки по этапам / B / R / T / Ограничения". Не путай минимальную фичу с сокращением необходимых проверок.
