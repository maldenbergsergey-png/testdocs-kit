# Создание сущности в админке и ссылки из функционального кейса

> Обезличенный демонстрационный пример. Все названия, пути, ссылки, ограничения и данные ниже вымышлены. В реальных кейсах их берут только из материалов текущего проекта. Пример иллюстрирует правила и не задаёт требования к продукту.

Условия примера:

- Тестовый профиль задаёт адреса админки и пользовательского сайта одной среды. Тестировщику разрешено создавать материалы.
- В разделе "Категории" есть тестовая категория, которую можно однозначно выбрать по названию и ID из её карточки. Она уже настроена для отображения материалов в каталоге.
- Во вкладке "Параметры" обязательны "Название" (от 1 до 80 символов), "Символьный код" (уникальные строчные латинские буквы, цифры и дефисы), "Категория" и "Статус". Для отображения в каталоге нужен статус "Опубликован".
- Во вкладке "Подробно" есть необязательные поля "Изображение" (PNG или JPEG) и "Описание" (от 1 до 160 символов при заполнении). Оба нужны для проверки блока материала на фронте. Подготовлен разрешённый тестовый файл изображения.
- После сохранения материал появляется в списке. При открытии на редактирование видны все сохранённые поля, выбранная категория и превью изображения.
- Опубликованный материал сразу доступен в каталоге по названию. Его карточка открывает `/catalog/[символьный код]/`. Блок материала содержит заголовок, изображение и описание из админки.
- Созданные данные сохраняют до окончания зависимых проверок. Затем создавший материал тестировщик удаляет его через действие "Удалить" в карточке с подтверждением. Ранее существующие материалы и категории не изменяют и не удаляют.

Скриншот не приложен: пример подготовлен по вымышленным текстовым требованиям. Реальное выполнение не проводилось.

## Административный кейс

В учебной TMS этому кейсу соответствует `EXAMPLE-T31`.

**Название:** Админка. Материалы. Создание опубликованного материала в категории

**Цель:** Проверить создание и сохранение материала с категорией и содержимым для пользовательского каталога.

Материалы:

- [Требования: поля и сохранение материала](https://docs.example.test/pages/materials)

**Предусловия:**

- Выбрана разрешённая тестовая среда. Тестировщик вошёл в админку с правом создания материалов.
- В разделе "Категории" есть тестовая категория для каталога; её название и ID видны в карточке.
- Подготовлен разрешённый тестовый файл изображения PNG или JPEG.

**Путь:** `/admin/materials/`

| № | Шаг | Тестовые данные | Ожидаемый результат |
| --- | --- | --- | --- |
| 1 | Открыть карточку тестовой категории в разделе "Категории" и записать её название и ID для выбора в форме материала. | Тестовая категория для каталога | В карточке видны название и ID выбранной категории. |
| 2 | Перейти в раздел "Материалы" и нажать "Создать материал". |  | Открывается форма создания с вкладками "Параметры" и "Подробно". |
| 3 | На вкладке "Параметры" заполнить обязательные поля:<br>• "Название"<br>• "Символьный код"<br>• "Категория"<br>• "Статус" | • Название: `Материал [маркер запуска]`, всего от 1 до 80 символов<br>• Символьный код: `material-[маркер запуска строчными латинскими буквами и цифрами]`, не занятый в этой среде<br>• Категория: название и ID из шага 1<br>• Статус: "Опубликован" | • В полях отображаются введённые название и символьный код<br>• Выбрана категория из шага 1<br>• Выбран статус "Опубликован" |
| 4 | На вкладке "Подробно" заполнить поля для блока материала:<br>• "Изображение"<br>• "Описание" | • Изображение: подготовленный тестовый PNG или JPEG<br>• Описание: `Описание тестового материала`, допустимая длина от 1 до 160 символов | • Отображается превью выбранного изображения<br>• В поле "Описание" отображается введённый текст |
| 5 | Нажать "Сохранить". |  | В списке "Материалы" появляется материал с введённым названием и статусом "Опубликован". |
| 6 | Открыть созданный материал на редактирование, сверить вкладки "Параметры" и "Подробно" с заполненными значениями. Записать символьный код для зависимого кейса. | • Название, код, категория и статус из шага 3<br>• Изображение и описание из шага 4 | • Название, символьный код, категория и статус сохранены с введёнными значениями<br>• Превью соответствует загруженному изображению<br>• Описание содержит введённый текст<br>• Символьный код созданного материала известен для открытия на фронте |

**Постусловия:** передать название, символьный код, изображение, описание и выбранную среду зависимому кейсу. Сохранить материал до завершения зависимых проверок. Затем создавший его тестировщик открывает карточку, нажимает "Удалить" и подтверждает удаление. Если зависимых проверок нет, выполнить очистку после этого кейса. Существующую категорию сохранить.

**Теги:** `e2e`, `web`, `админка`

**Статус:** `Черновик`

**Приоритет:** `Не определён`

Комментарий для TMS вне тела кейса: "Описано создание материала с категорией и содержимым; результат проверяется по сохранённым значениям в админке."

## Функциональный кейс с двумя видами ссылок

**Название:** Каталог. Блок материала. Открытие и отображение содержимого

**Цель:** Проверить открытие материала из каталога и отображение его заголовка, изображения и описания.

Материалы:

- [Требования: блок материала в каталоге](https://docs.example.test/pages/catalog-material)
- [Требования: поля материала](https://docs.example.test/pages/materials)
- [Требования: изображение и описание](https://docs.example.test/pages/materials#details)

**Предусловия:**

- Доступны пользовательский сайт и админка одной разрешённой тестовой среды.
- Тестировщику доступны просмотр материалов и их создание по административному кейсу.

**Путь:** `/catalog/[символьный код]/`

| № | Шаг | Тестовые данные | Ожидаемый результат |
| --- | --- | --- | --- |
| 1 | В разделе "Материалы" админки выбрать опубликованный тестовый материал в категории каталога с заполненными изображением и описанием. Если такого материала нет, выполнить [Создание опубликованного материала в категории](https://tms.example.test/testcases/EXAMPLE-T31). Если подходящий материал уже есть, пропустить создание. Зафиксировать его название, символьный код, изображение и описание. | ℹ️ Сверка сохранённых свойств описана в [Создании опубликованного материала в категории](https://tms.example.test/testcases/EXAMPLE-T31), шаг 6. | • Выбран опубликованный материал в категории каталога с изображением и описанием<br>• Название, символьный код, изображение и описание известны для следующих шагов |
| 2 | Открыть `/catalog/` и найти материал по выбранному названию. | Название из шага 1 | В каталоге отображается карточка выбранного материала с указанным названием. |
| 3 | Нажать на карточку материала. | Символьный код из шага 1 | Открывается `/catalog/[символьный код]/` выбранного материала. |
| 4 | Проверить заголовок, изображение и описание в блоке материала. | • Значения выбранного материала из шага 1<br>• ℹ️ "Название" настраивается в сущности [Материалы](https://docs.example.test/pages/materials) > вкладка "Параметры"<br>• ℹ️ "Изображение" и "Описание" настраиваются в сущности [Материалы](https://docs.example.test/pages/materials#details) > вкладка "Подробно"<br>• ℹ️ Заполнение изображения и описания показано в [Создании опубликованного материала в категории](https://tms.example.test/testcases/EXAMPLE-T31), шаг 4 на вкладке "Подробно" | • Заголовок равен названию выбранного материала<br>• Изображение соответствует выбранному в админке<br>• Описание равно сохранённому тексту |

**Постусловия:** если материал создан при подготовке, очистку выполняет создавший его тестировщик после всех зависимых проверок по административному кейсу. Ранее существующий материал сохранить.

**Теги:** `block`, `web`

**Статус:** `Черновик`

**Приоритет:** `Не определён`

Комментарий для TMS вне тела кейса: "Добавлена ссылка на подготовку с пропуском для подходящего материала и подсказки о настройке полей."
