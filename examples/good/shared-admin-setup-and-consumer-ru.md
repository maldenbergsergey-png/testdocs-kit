# Пример общего шага подготовки через админку

> Обезличенный демонстрационный пример. Вымышленное требование `R-EXAMPLE-31` определяет публикацию материала через панель управления и его отображение в пользовательском каталоге, а также относит открытие материала к часто используемой, но не блокирующей функции. В этом примере админка используется только как поверхность подготовки; её собственное регрессионное покрытие не входит в объём. Для создания достаточно названия и статуса; после сохранения в карточке доступен публичный путь.

## Переиспользуемая подготовка

**Название:** Подготовка данных: опубликованный материал

**Назначение:** Создать через панель управления опубликованный материал, который можно использовать в пользовательских сценариях.

**Требуемый доступ и начальная точка:**

- Тестировщику доступна панель управления с правом создания материалов.
- Открыта панель управления.

**Входные данные:**

- Название: `Материал [уникальный идентификатор запуска]`.
- Статус: `Опубликован`.

| № | Шаг | Тестовые данные | Ожидаемый результат |
| --- | --- | --- | --- |
| 1 | Перейти в раздел «Контент» → «Материалы». |  | Открывается список материалов. |
| 2 | Нажать «Создать материал». |  | Открывается форма создания материала. |
| 3 | Заполнить поле "Название". | `Материал [уникальный идентификатор запуска]` | В поле отображается введённое название. |
| 4 | Выбрать статус «Опубликован» и нажать «Сохранить». | Статус `Опубликован` | Форма закрывается, в списке отображается материал с указанным названием и статусом «Опубликован». |
| 5 | Открыть карточку сохранённого материала и записать публичный путь для зависимого кейса. | Название из входных данных | В карточке доступен публичный путь созданного материала. |

**Выход для зависимых кейсов:** название созданного материала и сформированный системой публичный путь.

**Очистка:** удалить созданный материал после выполнения всех зависимых кейсов, если правила тестовой среды требуют очистки.

**Отображение в Zephyr:** сохранить последовательность как именованный общий шаг. Зависимый кейс вызывает его один раз и использует зафиксированные название и публичный путь.

## Зависимый тест-кейс

**Название:** Каталог. Открытие опубликованного материала

**Цель:** Проверить открытие опубликованного материала из пользовательского каталога.

**Предусловия:**

- Доступны панель управления с правом создания материалов и пользовательский каталог одной тестовой среды.

**Путь:** `/catalog/`

| № | Шаг | Тестовые данные | Ожидаемый результат |
| --- | --- | --- | --- |
| 1 | Выполнить [Подготовку данных: опубликованный материал](#переиспользуемая-подготовка) и зафиксировать название и публичный путь. Если опубликованный тестовый материал уже есть, пропустить создание и записать эти данные из его карточки в панели управления. |  | Выбран опубликованный материал; известны его название и публичный путь. |
| 2 | Открыть `/catalog/` и найти выбранный материал по названию. | Название из шага 1 | В каталоге отображается карточка материала с указанным названием. |
| 3 | Нажать на карточку материала. | Публичный путь из шага 1 | Открывается публичный путь выбранного материала; на странице отображается указанное название. |

**Постусловия:** очистка созданного материала выполняется владельцем общего шага после завершения всех зависимых кейсов. Ранее существующий материал сохранить.

**Теги:** `block`, `web`

**Статус:** `Готов к ревью`

**Приоритет:** `Medium`
