# Понятные факт и комментарий

Учебные данные, не результаты реального прогона. Примеры показывают текст полей; реальные доказательства добавляются после него в соответствующие ячейки по [правилам отчёта](../../rules/execution-report-rules.md).

| Проверка | Ожидаемый результат | Фактический результат | Комментарий | Статус |
| --- | --- | --- | --- | --- |
| Порядок цен в открытом списке | Проекты расположены от меньшей цены к большей. | Цены идут не по возрастанию: после 10 700 000 показано 7 600 000. | [Каталог: Порядок цен](https://requirements.example.test/catalog#price). Запуск после очистки данных не проверен. | НЕ OK |
| Закрытие формы | После сохранения окно закрывается. | Данные сохранились, но окно осталось открытым. | Требование из чата. | НЕ OK |
| Поиск без совпадений | Показан текст "Ничего не найдено". | Показан текст "Ничего не найдено". | | OK |
| Отправка обязательных полей | В запросе есть поля name и phone. | | Тело запроса не удалось получить. | НЕ ПРОВЕРЕНО |
| Отмена заказа через API | После отмены status равен CANCELLED. | POST /api/orders/42/cancel вернул 200, но status остался ACTIVE. | [Заказы: Отмена](https://requirements.example.test/orders#cancel). | НЕ OK |

В первом примере сетевой захват также показывает порядок цен. Дополнительный запрос с другим параметром получил 400, но этот параметр приложение не отправляло. Эти сведения остаются в диагностических материалах с точным происхождением; ни "QA-запросы", ни версия о виновности бэкэнда не нужны для понимания UI-дефекта. Корректная сортировка после отдельного действия не отменяет наблюдение об исходном списке.

В API-примере метод, адрес, код и поле необходимы для понимания результата. Реальное тело ответа добавляется после короткого текста по правилам доказательств, без пересборки и изменения. Краткость не означает удаление доказательств или замену факта фразой "Не работает".
