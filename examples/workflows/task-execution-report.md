# Отчёт о выполнении с текстовыми данными и скриншотом

Учебный пример: все требования, наблюдения и имена файлов вымышлены. Ссылку на изображение в реальном отчёте добавляют только после загрузки соответствующего доказательства.

Исходные сведения примера:

- После сохранения формы окно должно закрыться. В тестовом прогоне оно закрылось; сохранён снимок итогового экрана.
- Пока сервер отвечает, на кнопке "Сохранить" должен быть индикатор загрузки. Увидеть его не удалось. В коде есть переключение состояния загрузки, но это не наблюдение на экране.
- API должен отклонять неподдерживаемый тип клиента кодом 400 с указанием причины. Получен ответ 400 и показанное ниже JSON-тело. Апостроф в значении customerName - часть исходных данных.

```text
h2. Сохранение заявки
||Номер||Проверка||Как проверить||Ожидаемый результат||Фактический результат||Комментарий||Статус||
|1.|Закрытие формы|Заполнить форму и нажать "Сохранить"|Окно закрывается|После нажатия "Сохранить" окно закрылось. \\ Форма закрыта: !1-actual-01.png!| |{color:#14892c}*OK*{color}|
|2.|Индикатор загрузки|Нажать "Сохранить" и посмотреть на кнопку до ответа сервера|На кнопке виден индикатор загрузки до ответа сервера|Увидеть индикатор загрузки не удалось. Его отображение не проверено.|Для повторной проверки нужен замедленный ответ тестового сервера.|{color:#6b778c}*НЕ ПРОВЕРЕНО*{color}|
|3.|Неподдерживаемый тип клиента|Отправить POST /api/applications с неподдерживаемым типом клиента|Сервер возвращает код 400 и объясняет причину отказа|Сервер вернул код 400: тип клиента не поддерживается. Ответ: {code:json}{"error":"unsupported_customer_type","customerName":"O'Connor"}{code}| |{color:#14892c}*OK*{color}|
```

В первой строке скриншот находится внутри фактического результата, комментарий пуст. Во второй строке описание кода не подменяет проверку индикатора. В третьей строке короткий ответ читается прямо в ячейке; отдельный JSON/TXT-файл не нужен. Эти пояснения относятся к примеру и не добавляются в пользовательский отчёт.
