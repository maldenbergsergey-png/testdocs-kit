# Проверка поиска документов с доработками

Следовать независимой офлайн-процедуре [README](README.md). Передать агенту только [knowledge-discovery.json](knowledge-discovery.json), discovery descriptions и выбранные инструкции, без этого файла с критериями. Получить выбранный скилл, точный ответ, следующие чтения и границы готового результата. Контекст считать наблюдённым; живые сервисы не вызывать, результаты сохранять вне репозитория. Повторить общую routing-процедуру.

Оценить реальные решения:

- Основная страница без ссылок не считается полным набором требований: запрашиваются дочерние страницы и ограниченный поиск по названию функции, читаются релевантные доработки. Название с префиксом задачи не отбрасывается как дубль. Дерево на снимке не подменяет чтение тела.
- Пустой список детей не завершает поиск: используется известная область DOCS, название функции и точный ключ задачи. Нет запроса разрешения на уже ограниченное чтение, произвольного выбора компании или экспорта всего пространства.
- При старте с доработки читается основная страница и релевантные соседи. Метаданные помогают отобрать кандидатов; похожее слово «проект» не делает другую карточку частью scope автоматически.
- В новом чате неизменные версии известных страниц допускают повторное использование текста, но требуют обновить дерево/поиск для обнаружения новых страниц. Полный свежий результат текущей задачи не запрашивается повторно без причины.
- size=25 не считается общим количеством. Следующая порция остаётся необходимой; недоступная страница и её сниппет не превращаются в прочитанное требование или доказанное отсутствие изменений. Возвращается PARTIAL_CONTEXT и конкретный пробел, независимые данные сохраняются.
- В конфликтном сценарии повторённые требования объединены, заголовок остаётся готовой частью. Применимость 202 уточняется до готовой проверки отсутствующей цены; дата и Done не определяют приоритет. Изменение 4.3 не попадает в ожидание 4.2. Источники использованных требований и конфликтов сохранены, тестирование не выдумано.
- При достаточном ручном вводе нет внешнего поиска и вопроса о компании ради него, в том числе если полный актуальный текст снабжён лишь URL происхождения без установленной области знаний. Явное ограничение одной версией соблюдается; результат не объявляется полным покрытием текущей функции по всем источникам.

Запустить `npm test`, проверить формат реально сформированных кейсов/чек-листов существующими валидаторами. MCP-фикстуры отдельно проверяют продолжение offset/cursor, поздние дочерние страницы, неизвестные totals и ancestry через текущий адаптер. Офлайн-оценка не подтверждает доступ к живой Confluence или полноту её поискового индекса.
