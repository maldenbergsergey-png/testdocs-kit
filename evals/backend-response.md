# Подлинность ответа бэкэнда

Передать независимому агенту только [сценарии](backend-response.json) и текущий pack. Сначала читать discovery descriptions, затем выбранные скиллы и условные правила. `context` - уже наблюдённые факты; `body`, когда дано, - точный исходный текст после декодирования JSON корпуса. Не выполнять живые запросы, публикацию или скачивание. Не показывать агенту критерии ниже. Сохранить вне репозитория `{id, skill, response, next_actions}` с реальными ответами и payload, когда он запрошен. Общая процедура - в [README](README.md).

Проверить ответы по содержанию, а не по упоминанию правил:

- Маленькое тело целиком внутри Jira `{code}`/`{code:json}` и посимвольно совпадает с `body`; пробелы, переносы, порядок, `1.00`, строковый ID, `null`, апостроф, `|`, escape-последовательности и завершающий перенос сохранены. Нет новых полей, выбранных вместо ответа объектов или pretty-print. HTTP-статус и объяснение снаружи.
- Собственный `backend-evidence.json` не принимается за ответ сервера; запланировано чтение исходной сетевой операции, без реконструкции и повторного прогона под видом старого ответа. При наличии только разобранного объекта исходный body честно назван недоступным.
- Для большого ответа выбран исходный файл, а не его пересборка; фрагмент является непрерывной подстрокой `body`, помечен и связан с полным файлом. Нет добавленных скобок, многоточий или склеивания разрозненных полей. Не требуется, чтобы выдержка сама была валидным JSON.
- Невалидное тело HTTP 502 не исправлено и не дополнено, сохранено в обычном `{code}`. Ошибка формата объяснена отдельно.
- Секрет и персональные данные не повторены. Обезличенная копия явно названа, скрытые поля перечислены снаружи без значений; неизменённые части тела сохранены. Нет обещания сохранить запрещённый исходник.
- JSON payload транспорта после декодирования содержит тот же текст тела в блоке. Существующий маленький `.json` показан inline, без ненужной загрузки файла. Публикация нигде не заявлена выполненной.

Сверить строки программно, где возможно; ручная проверка должна также оценить честность происхождения и следующих действий. Повторить общую маршрутизацию и подходящие сценарии [reporting.json](reporting.json). Офлайн-ответы не подтверждают реальный рендеринг Jira/QA Report или перехват сетевого ответа.
