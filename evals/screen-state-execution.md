# Проверка выполнения по состояниям экрана

В независимом контексте передать агенту только [корпус](screen-state-execution.json) и текущий pack. Не передавать критерии ниже, diff или прошлые ответы. `context` считать уже наблюдёнными фактами; выполнять только офлайн-репетицию, без живых вызовов и внешних записей. Для каждого сценария сохранить вне репозитория `{id, skill, response, actions, rows}`: точный ответ, упорядоченные следующие действия и результаты строк, когда для них достаточно фактов. Не выдумывать результаты будущих действий.

Проверить реальные решения и порядок действий:

- Функциональные и доступные нефункциональные проверки выполняются при посещении нужного состояния; исходная модалка снимается до отправки/закрытия. Независимые критерии сохраняют свои номера и результаты.
- Недоступный макет запрашивается своевременно, наблюдаемое состояние сохраняется с контекстом для отложенной сверки. Независимые проверки продолжаются, зависимая сверка не становится `OK` и не исчезает из scope.
- При позднем макете сначала используются отчёт, индекс и пригодные файлы. Отсутствующий индекс восстанавливается по подтверждённым материалам. Отдельные новые визуальные критерии добавляются явно, без переписывания исходных функциональных результатов.
- Полный старый снимок позволяет оценить вид исходной сборки без нового функционального прогона. Недостающая ошибка требует только её воспроизведения; новая сборка требует нового наблюдения запрошенного экрана, сохраняя историю старой.
- Итоговый снимок не подтверждает загрузку или работу клавиатуры. Для недостающих динамических критериев планируется нужное взаимодействие/видео, а уже доступная статическая сверка используется повторно.
- Один файл допускает несколько привязок, но функциональный успех не скрывает визуальный дефект. Явное исключение нефункциональных проверок сохраняется.

Повторить [design-preflight.json](design-preflight.json) по процедуре из [README](README.md). Это проверка решений по наблюдённому контексту, а не доказательство качества живого захвата или полного отсутствия повторных переходов в реальном приложении.
