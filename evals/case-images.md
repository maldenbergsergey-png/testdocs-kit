# Изображения в шагах тест-кейсов

Использовать [корпус](case-images.json) и текущий pack по [независимой процедуре](README.md), без живых вызовов. Передавать агенту JSON без критериев ниже; `context` считать уже полученными фактами. Сохранять вне репозитория `{id, skill, response, next_actions, payloads}`. Для запрошенных полных кейсов сохранять Markdown отдельно и запускать `scripts/validate-test-case-format.mjs`.

После прогона проверить:

- Кейсы без изображений готовы без обязательного вопроса; при выбранных изображениях уточняются только недостающие источник/адрес. Независимый текст готовится параллельно, согласие на скрины не считается публикацией.
- Макет выбирается из требований или явного указания. Захват ограничен нужным фреймом/блоком с ориентирами, не общим окном Figma. Запланирована проверка сохранённого файла; не выдуман экспорт. Реализация подписана отдельно и не меняет ожидания требований.
- Иллюстрация размещается мини-превью под текстом конкретной ячейки «Шаг» или «Ожидаемый результат», с открытием полного размера и сохранением пропорций. Вложение или ссылка без превью недостаточны. Действие и ожидание остаются текстовыми, четыре колонки сохранены. Старые изображения сохраняются при независимой текстовой правке. Diff удаления/замены указывает старый материал, шаг и причину.
- Стрелки и прямоугольники накладываются точным инструментом на отдельную копию, исходник и происхождение сохраняются. Нужные элементы выделены без перекрытия текста и перерисовки UI; стрелка-аннотация не считается служебным указателем. Локальное прикрепление к черновику не становится публикацией в TMS.
- Старые кейсы остаются proposal-only, в том числе при работе только со скрином. Новый кейс из этого чата допускает явную разрешённую загрузку с registry, без setup opt-in. Для отображаемого шага 2 используется прочитанный API index=1 и текущий hash, не номер 2.
- Неопределённая загрузка не повторяется автоматически; сохраняются ключ кейса, известные ID и частичные результаты. Чтение и визуальная проверка различаются.
- Отсутствие функций загрузки/замены/удаления явно обозначено. Подготовленные материалы сохраняются, нет выдуманного API, нового публичного хостинга, смены TMS, удаления через внутренний endpoint или замены script ради удаления вложения. Частичное выполнение не выдаётся за готовый результат со скринами.

Повторить общую routing-процедуру, [case-write-intent.json](case-write-intent.json) и относящиеся к кадрированию сценарии [source-evidence.json](source-evidence.json). MCP-тесты отдельно проверяют реальные байты, multipart и guards в изолированных фикстурах. Офлайн-оценка не доказывает отображение изображений в живом TMS.
