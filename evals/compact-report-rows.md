# Проверка кратких строк отчёта

Следовать независимой офлайн-процедуре [README](README.md): передать агенту только [compact-report-rows.json](compact-report-rows.json), discovery descriptions и выбранные инструкции, без этого файла с критериями. Получить реальные ответы, сохранить вне репозитория. Повторить подходящие сценарии [reporting.json](reporting.json): `observed_ui_and_api`, `backend_relevant_excerpt`, `status_threshold_and_real_gaps`. Никаких внешних вызовов и записей.

Поля `request`, `body` и `log`, когда даны, содержат точный исходный текст после декодирования JSON корпуса. При оценке сопоставить с ними блоки ответа, не только смысл описания.

После прогона оценить ответы:

- По ожиданию и факту сразу понятно конкретное отличие. Описание факта обычно занимает 1-2 коротких предложения, без хронологии, догадок о причине и служебных названий вроде "QA-запрос". Источник, ограничения и доказательства не подменяют текст отличия.
- Для сортировки достаточно одного подтверждающего примера инверсии цен. Не приписываются чистый запуск, ошибка API приложения или виновный компонент. Ручная пересортировка не замещает исходное наблюдение, а диагностические запросы не превращаются в новые продуктовые проверки.
- Комментарий содержит нужные именованные источники и короткое существенное ограничение/вопрос, либо пуст. Нет пересказа факта, прежних статусов и описания расположения вложений. Указания перенести снимок в ячейку не включены в готовый текст полей; при необходимости это отдельное действие доставки. Сетевые ID и история остаются в диагностических материалах с происхождением.
- Текст результата описывает приложение: в открытой карточке на iOS баннер виден, на Android не отображается. Нет оборотов "на снимке", "по скриншоту", "момент съёмки" и их замены на "момент проверки". Разные сделки и несопоставленное состояние оплаты сохранены как ограничение; неизвестные условия показа остаются вопросом со статусом ТРЕБУЕТ УТОЧНЕНИЯ. Нет версии об устаревших данных, подтверждённого дефекта Android или обобщения одной карточки на платформу.
- Для статичного поиска названы поле со значением и сообщение, комментарий пуст. Не выдуманы ввод, переход или самостоятельное взаимодействие; уже указанный во вводных способ проверки не повторяется. В сценарии оплаты сохранены продуктовые интервалы 10 и 30 секунд и НЕ OK: удалён рассказ о съёмке, а не время наблюдаемого поведения. Источник требования из чата допустим в комментарии.
- В строке быстрого входа названы цифры и удаление; комментарий пуст. Нет пересказа задания с упоминанием заказчика или его обезличенной замены "по запросу". Возврат телефона в исходное положение и ненужное разрешение снимка убраны. Текст читается как запись автора отчёта, без выдуманного "я проверил".
- В строке горизонтального положения названо, что именно не видно. Нет истории подключения Figma и уборки после проверки. Недоступность макета и вопрос о поддержке этого положения сохранены простыми словами, статус ТРЕБУЕТ УТОЧНЕНИЯ; ожидающий ответа запрос не превращён в отмену сверки или завершение всего прогона. В отдельном сценарии обратного поворота сохранён наблюдаемый результат: кнопка "Продолжить" снова видна. Служебный возврат среды отличается от проверяемого поведения по смыслу, а не по наличию слова "ориентация".
- Для подтверждённой серверной причины в мобильной и web-строке комментарий содержит английскую метку `BE`; она не заменяет статус и не добавляет колонку. В сценарии сортировки с неподтверждённой причиной метки нет. В ошибочной строке перечислены нумерованные действия воспроизведения, только из известных фактов.
- Для API остаются значимые метод, адрес, HTTP-код и поле. Исходный ответ сохраняет все символы, включая пробел и апостроф. Для UI нет ненужного пересказа сети. Отдельный ручной запрос не доказывает отправку данных приложением; ненаблюдавшийся факт пуст, статус НЕ ПРОВЕРЕНО.
- Частичное покрытие явно отмечено; сокращение не удаляет непроверенную часть или причину. При конфликте правил вопрос сформулирован обычными словами, обе ссылки сохранены, статус ТРЕБУЕТ УТОЧНЕНИЯ. Подтверждённое нарушение остаётся НЕ OK при неизвестной причине.
- После перепроверки в строке один актуальный факт без датированных дополнений и перечня диагностических запросов. В бронировании сохранены наблюдения гостя и авторизованного состояния, оба снимка привязаны к факту; вопрос о can_reserve=false и обе именованные ссылки находятся в комментарии. При неизвестном правиле статус ТРЕБУЕТ УТОЧНЕНИЯ; флаг не объявлен доказательством ограничения данных или серверной причины. При однозначном требовании кнопки независимо от флага - НЕ OK без лишнего вопроса о причине. При известном обязательном can_reserve=true и отсутствии подходящих данных факт перехода пуст, статус НЕ ПРОВЕРЕНО, запрос данных остаётся ожидающим ответа. Скрытая кнопка при false не выдаётся за выполнение проверки перехода.
- Успешная перепроверка исправления получает актуальный факт и OK с новым снимком. Старое нарушение не остаётся текущим фактом; исходные наблюдение, снимок и сведения о сборке сохраняются в истории, без перезаписи файлов. Нет выдуманной доставки вложений.
- Сохранённые снимки и тела ответов остаются в соответствующих ячейках по контракту доказательств, а не удаляются ради короткого текста. Доказательства не считаются сохранёнными в назначении без записи.
- Для небольшого checklist две самостоятельные проверки покрывают оба требования, факт и статус пусты. Нет дополнительных сценариев ради количества строк, формальных разделов, вопросов и повторного пересказа требований в сопровождении.
- Для backend основными материалами служат точные исходные запрос и ответ, отдельно - относящийся к той же операции лог. Нет скриншотов API-клиента вместо текста, логов чужого запроса и общего сетевого дампа при уже сохранённой операции. Короткое описание называет status=ACTIVE вместо CANCELLED; подтверждённый откат не превращается в выдуманную первопричину.
- Для UI выбран читаемый кадр формы с полем и кнопкой, подпись называет подтверждаемый факт. Нет изолированной кнопки без ориентиров, дублей, гипотезы о сервере и метки BE. Ненужное расследование удалено; отсутствие изображения ожидания не скрыто.

Запустить `npm test`. Проверка структуры и анализ реальных ответов дополняют друг друга; поиск слов в инструкциях не подтверждает поведение. Офлайн-результат не доказывает отображение или сохранение в живом QA Report.
